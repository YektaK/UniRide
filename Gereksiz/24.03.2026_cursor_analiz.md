Bunu iki şekilde yapabiliriz:

- **Yöntem A (en hızlı):** Supabase SQL Editor’dan şu sorgu çıktılarını paylaş:
  - `select count(*) from time_matrix;`
  - `select origin_code, count(*) as cnt from time_matrix group by origin_code order by cnt desc;`
  - `select * from time_matrix where origin_code='D.Kampus' and destination_code='Sw1' limit 1;`
  - `select column_name from information_schema.columns where table_name='time_matrix';`

- **Yöntem B (benim doğrudan kontrol etmem):**
  - Bu makinede çalışan servislerde `SUPABASE_URL` ve `SUPABASE_SERVICE_ROLE_KEY` erişilebilir olmalı (env’de).
  - Ardından ben localden script/endpoint ile tablo doluluk, kolon uyumu ve örnek edge doğrulamasını çalıştırırım.

Ek olarak Python optimizer logunda şu mesajı görmemiz gerekir: time matrix’in Supabase’ten yüklendiğini belirten log; fallback/log varsa problem teyit edilir.

## Genel Değerlendirme

- Mimari niyetin doğru: UI -> Next API -> Python optimizer -> Supabase.
- En büyük risk, **isimlendirme ve payload kontratlarının** tutarsız olması.
- Şu an en kritik düzeltme hedefi:
  1) Tek “canonical algorithm key” sözlüğü,  
  2) `route-test` payload düzeltmesi,  
  3) `two-opt` için gerçek Python strategy (veya açıkça kaldırma/yeniden etiketleme),  
  4) time matrix yüklenmediğinde “sıfır matris” yerine fail-fast veya güçlü fallback.

İstersen bir sonraki adımda bu 4 başlık için doğrudan kod düzeltmelerini yapayım ve ardından admin ekranlarından uçtan uca test checklist’i çıkarayım.
