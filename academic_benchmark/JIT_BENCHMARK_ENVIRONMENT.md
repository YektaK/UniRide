# Reproducible JIT Benchmark Environment

## Purpose

The academic benchmark deliberately supports a Python objective fallback when
Numba is unavailable.  That fallback preserves functionality, but it is **not
evidence that the accelerated GWO/HHO matrix objective has been validated**.
Use this isolated profile before collecting or publishing performance claims
that depend on JIT acceleration.

The repository's normal dependency declaration intentionally leaves `numpy`
and `numba` unconstrained.  The constraints below pin a tested compatibility
set without changing any developer's active interpreter:

| Component | Pinned version |
| --- | --- |
| Python | `>=3.11,<3.15` |
| NumPy | `2.4.6` |
| llvmlite | `0.48.0` |
| Numba | `0.66.0` |

Numba 0.66.0 documents support for Python `>=3.10,<3.15`, NumPy
`>=2.0,<2.5`, and llvmlite `0.48.x`.  This profile narrows Python to
`>=3.11,<3.15` because NumPy 2.4.6 requires Python 3.11 or newer.  NumPy
2.4.6 is intentionally selected instead of the yanked NumPy 2.4.0 release.

Authoritative compatibility references:

- [Numba version support table](https://numba.readthedocs.io/en/stable/user/installing.html)
- [Numba 0.66.0 package release](https://pypi.org/project/numba/)
- [llvmlite 0.48.0 package release](https://pypi.org/project/llvmlite/)
- [NumPy 2.4.6 package release](https://pypi.org/project/numpy/2.4.6/)

## Create the isolated environment

Run these commands from the repository root.  They create and modify only
`.venv-jit`; do not install these pins into an existing development
environment.

```powershell
python -m venv .venv-jit
.\.venv-jit\Scripts\python.exe -m pip install --upgrade pip
.\.venv-jit\Scripts\python.exe -m pip install -e ".[test]" -c academic_benchmark/jit-benchmark-constraints.txt
.\.venv-jit\Scripts\python.exe -m pip check
```

If the selected `python` is outside the documented Python range, select a
supported CPython interpreter when creating `.venv-jit`; do not relax the
NumPy or llvmlite pins.

## Verify accelerated execution

The parity test uses `solve_with_matrix(..., closed_tsp=True,
recalculate=False)`, which ensures the reported GWO/HHO result is produced by
the same cached matrix objective path used during search.  It compares a
test-local forced Python fallback with the real JIT kernel for fixed-seed,
symmetric TSP and directed ATSP instances.  It independently recomputes every
closed cycle, verifies a complete permutation, and requires identical route,
cost, and objective-evaluation count.

```powershell
.\.venv-jit\Scripts\python.exe -m pytest academic_benchmark/tests/test_numba_jit_parity.py -q -p no:cacheprovider --tb=short
```

Interpret the result as follows:

- `passed`: the Numba kernel compiled in nopython mode and matched the Python
  fallback for both GWO and HHO on symmetric and asymmetric matrices.
- `skipped`: Numba was genuinely unavailable at import time.  The current
  interpreter can use the Python fallback, but it is not JIT-validated.
- `failed`: a JIT-capable environment produced a compilation, numerical,
  route, or accounting mismatch.  Do not use that environment for benchmark
  evidence until the failure is resolved.

The test never changes `NUMBA_AVAILABLE`, solver configuration defaults, or
benchmark output.  The fallback is forced only through pytest's scoped
monkeypatch so both backend paths are compared within one deterministic test.

## Required verification before a performance run

```powershell
.\.venv-jit\Scripts\python.exe -m pytest academic_benchmark/tests/test_numba_jit_parity.py academic_benchmark/tests/test_fair_comparison_protocol.py academic_benchmark/tests/test_fair_comparison_scientific_integrity.py academic_benchmark/tests/test_numba_registry_matrix.py academic_benchmark/tests/test_atsp_integration.py -q -p no:cacheprovider --tb=short
.\.venv-jit\Scripts\python.exe -m pytest academic_benchmark/tests -q -p no:cacheprovider --tb=short
```

Record the interpreter version, package versions, parity-test result, command,
problem set, random seeds, evaluation budget, and timing method alongside any
reported GWO/HHO performance claim.  Do not compare timings generated by the
Python fallback with timings generated in this JIT profile.
