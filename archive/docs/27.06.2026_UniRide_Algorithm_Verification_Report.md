## 2. Critical Vulnerabilities (Deep Dive)

### VULN-1: Distance Rounding Inconsistency — Silent TSPLIB Benchmark Corruption

**Severity: CRITICAL** — Makes benchmark comparisons between solver families invalid.

**The Bug:** Three different Euclidean distance implementations coexist with three different rounding rules:

| Function | File | Rounding | TSPLIB Correct? |
|----------|------|----------|:---:|
| `euclidean_distance()` | `bildiri2026/core/base_solver.py:147` | `int(math.sqrt(...) + 0.5)` (NINT) | Yes |
| `euclidean_distance_2d()` | `uniride_core/algorithms/distance.py:62` | Raw float, no rounding | No |
| `tsplib_euc_2d_distance()` | `uniride_core/algorithms/distance.py:69` | `int(round(...))` (banker's) | No |
| `create_np_distance_matrix()` | `uniride_core/algorithms/distance.py:143` | `int(round(...))` (banker's) | No |

**The Proof (CodeGraph-traced):**
- `uniride_core/algorithms/sota_tsp/base_solver.py:76` calls `euclidean_distance_2d()` → raw float distances
- `academic_benchmark/bildiri2026/core/base_solver.py:147` uses `int(math.sqrt(dx*dx + dy*dy) + 0.5)` → NINT integer distances
- Python's `round(2.5)` returns `2` (banker's rounding to even), not `3` (TSPLIB NINT)
- For berlin52: the optimum is 7542 under NINT. Under raw float, the optimum is ~7544.5. Under banker's rounding, it may differ again.

**The Fix:**

```python
# distance.py — BEFORE (line 69)
def tsplib_euc_2d_distance(p1, p2) -> int:
    return int(round(euclidean_distance_2d(p1, p2)))

# distance.py — AFTER
def tsplib_euc_2d_distance(p1, p2) -> int:
    d = euclidean_distance_2d(p1, p2)
    return int(d + 0.5)  # TSPLIB NINT: round half up, not banker's rounding

# distance.py — BEFORE (line 143)
d = float(int(round(math.hypot(xi - xj, yi - yj))))

# distance.py — AFTER
d = float(int(math.hypot(xi - xj, yi - yj) + 0.5))

# sota_tsp/base_solver.py — BEFORE (line 76)
def euclidean_distance(p1, p2) -> float:
    return float(euclidean_distance_2d(p1, p2))

# sota_tsp/base_solver.py — AFTER (use TSPLIB NINT for EUC_2D)
def euclidean_distance(p1, p2) -> float:
    return float(int(euclidean_distance_2d(p1, p2) + 0.5))
```

### VULN-2: ALNS GreedyInsertion Time-Window Feasibility Stub

**Severity: CRITICAL** — Silently produces infeasible CVRPTW solutions.

**The Bug:** `_is_tw_feasible()` in `sota_common/repair_operators.py:118-128` always returns `True` regardless of actual time window constraints.

**The Proof:**
```python
# sota_common/repair_operators.py:118-128
def _is_tw_feasible(node: str, pos: int) -> bool:
    """Check if insertion at *pos* respects time windows."""
    if node not in tw:
        return True  # No TW constraint
    # Simplified: just check node TW exists
    return True  # ← ALWAYS TRUE! Never checks actual TW bounds
```

The function captures `tw` (time windows dict) but the "simplified" check on line 128 unconditionally returns `True`. The call at line 139 `if not _is_tw_feasible(node, pos): continue` is dead code — no position is ever skipped.

**The Fix:**
```python
# BEFORE (line 118-128)
def _is_tw_feasible(node: str, pos: int) -> bool:
    if node not in tw:
        return True
    # Simplified: just check node TW exists
    return True

# AFTER — check that inserting node doesn't push arrival past latest
def _is_tw_feasible(node: str, pos: int) -> bool:
    if node not in tw:
        return True
    earliest, latest = tw[node]
    # Approximate: compute arrival time at node given prev arrival
    # (full propagation is caller's job, but this catches gross violations)
    if pos == 0 or not current:
        return True  # first stop — no upstream delay
    prev = current[pos - 1]
    # Accumulate travel from depot through chain (simplified)
    arrival = 0
    chain = [current[k] for k in range(pos)] + [node]
    for k in range(len(chain) - 1):
        arrival += _dist(chain[k], chain[k + 1])
    if arrival > latest:
        return False
    return True
```

### VULN-3: Regret-2 / Regret-3 Insertion Completely Ignores Time Windows

**Severity: CRITICAL** — Both regret operators accept `time_windows` kwarg but never use it.

**The Proof:**
```python
# sota_common/repair_operators.py:185-186 (Regret2Insertion)
dist: Dict[str, Dict[str, float]] = kwargs.get("distance_matrix", {})
tw: Dict[str, Tuple[float, float]] = kwargs.get("time_windows", {})  # captured...
# ...but tw is NEVER referenced again in the insertion loop (lines 212-242)
```

The `tw` variable is captured on line 186 but is never used in the `_eval_positions` function or the main `while remaining:` loop. No feasibility filtering occurs. The same pattern exists in `Regret3Insertion` at line 276.

**The Fix:**
```python
# Regret2Insertion.repair() — add feasibility filter in _eval_positions

# BEFORE (line 194-210)
def _eval_positions(node: str) -> List[Tuple[float, int]]:
    costs = []
    for pos in range(len(current) + 1):
        ...
        costs.append((c, pos))
    costs.sort()
    return costs

# AFTER — skip TW-infeasible positions
def _eval_positions(node: str) -> List[Tuple[float, int]]:
    costs = []
    for pos in range(len(current) + 1):
        if node in tw and pos > 0:
            # Simple TW check: would inserting here push past latest?
            earliest, latest = tw[node]
            # (caller should do full propagation; this is a guard)
            pass  # delegate to _is_tw_feasible if available
        n = len(current)
        prev = current[pos - 1] if pos > 0 else None
        nxt = current[pos] if pos < n else None
        c = 0.0
        if prev and nxt:
            c = _dist(prev, node) + _dist(node, nxt) - _dist(prev, nxt)
        elif prev:
            c = _dist(prev, node)
        elif nxt:
            c = _dist(node, nxt)
        costs.append((c, pos))
    costs.sort()
    return costs
```

### VULN-4: sota_tsp GreedyInsertion — Missing Bypass Cost at Tour Boundaries

**Severity: HIGH** — Biases insertion toward middle positions, producing sub-optimal repairs.

**The Bug:** In `sota_tsp/repair_ops.py:27-29`, the bypass cost `d(prev, next)` is only subtracted when `0 < pos < len(result)`. At `pos=0` and `pos=len(result)`, the insertion cost is inflated because it doesn't account for the edge being broken.

**The Proof:**
```python
# sota_tsp/repair_ops.py:22-29
prev_node = result[pos - 1] if pos > 0 else result[-1] if result else node  # cyclic: prev = last
next_node = result[pos] if pos < len(result) else result[0] if result else node  # cyclic: next = first
if not result:
    cost = 0.0
else:
    cost = dm[prev_node][node] + dm[node][next_node]
    if pos > 0 and pos < len(result):  # ← bypass only for middle positions!
        cost -= dm[prev_node][next_node]  # ← NOT subtracted at pos=0 or pos=len
```

For a cyclic TSP tour, inserting at pos=0 breaks the edge `result[-1] → result[0]`. The true insertion cost is `d(last, node) + d(node, first) - d(last, first)`, but the code computes `d(last, node) + d(node, first)` (no subtraction). This overestimates the cost, biasing the operator away from boundary insertions.

Same bug exists in `RegretKInsertion` at lines 58-60 and 88-90.

**The Fix:**
```python
# sota_tsp/repair_ops.py GreedyInsertion — BEFORE (line 27-29)
cost = dm[prev_node][node] + dm[node][next_node]
if pos > 0 and pos < len(result):
    cost -= dm[prev_node][next_node]

# AFTER — always subtract bypass for cyclic tour
cost = dm[prev_node][node] + dm[node][next_node]
if len(result) >= 2:
    cost -= dm[prev_node][next_node]  # always subtract for cyclic TSP
```

Apply the same fix to `RegretKInsertion` at lines 58-60 and 88-90.

### VULN-5: K-Means Clustering Non-Determinism — Global Random Module

**Severity: HIGH** — Benchmark results cannot be reproduced.

**The Bug:** `clustering.py` uses `random.randint()` and `random.random()` (module-level global state) instead of a seeded `random.Random` instance.

**The Proof:**
```python
# uniride_core/algorithms/clustering.py:45
first_idx = random.randint(0, len(points) - 1)  # ← global random, no seed

# clustering.py:61
threshold = random.random() * total_dist  # ← global random, no seed
```

The `kmeans_clustering` function at line 72 accepts no `seed` parameter. The `VehicleCalculator` class that calls it also passes no seed. Every run produces different cluster assignments.

**The Fix:**
```python
# clustering.py — BEFORE (line 40)
def initialize_centroids_kmeans_plus_plus(points: List[Point], k: int) -> List[Tuple[float, float]]:
    ...
    first_idx = random.randint(0, len(points) - 1)
    ...
    threshold = random.random() * total_dist

# AFTER — accept seeded rng
def initialize_centroids_kmeans_plus_plus(
    points: List[Point], k: int, rng: Optional[random.Random] = None
) -> List[Tuple[float, float]]:
    rng = rng or random.Random(42)  # default seed for reproducibility
    ...
    first_idx = rng.randint(0, len(points) - 1)
    ...
    threshold = rng.random() * total_dist

# kmeans_clustering — also accept rng parameter
def kmeans_clustering(
    points: List[Point], k: int, max_iterations: int = 100, rng: Optional[random.Random] = None
) -> List[Cluster]:
    rng = rng or random.Random(42)
    ...
    centroids = initialize_centroids_kmeans_plus_plus(points, k, rng)
```

## 3. Redundancy & Conflict Check

### CONFLICT-1: Three Euclidean Distance Implementations

| Implementation | Rounding | Used By |
|----------------|----------|---------|
| `bildiri2026/core/base_solver.py:euclidean_distance` | `int(sqrt + 0.5)` (NINT) | bildiri2026 GA/PSO/GWO/HHO |
| `uniride_core/algorithms/distance.py:euclidean_distance_2d` | Raw float (no rounding) | sota_tsp base_solver |
| `uniride_core/algorithms/distance.py:tsplib_euc_2d_distance` | `int(round(...))` (banker's) | tsplib_parser |

**Unified Kernel Proposal:**
```python
# uniride_core/algorithms/distance.py — single source of truth

def tsplib_euc_2d_distance(p1: Tuple[float, float], p2: Tuple[float, float]) -> int:
    """TSPLIB EUC_2D: NINT(sqrt(dx² + dy²)) — round half UP, not banker's."""
    return int(math.sqrt((p1[0]-p2[0])**2 + (p1[1]-p2[1])**2) + 0.5)

def euclidean_distance_2d(p1: Tuple[float, float], p2: Tuple[float, float]) -> float:
    """Raw Euclidean — for non-TSPLIB use only."""
    return math.sqrt((p1[0]-p2[0])**2 + (p1[1]-p2[1])**2)

# ALL solvers should use tsplib_euc_2d_distance for TSPLIB benchmarking
# bildiri2026/core/base_solver.py should import from distance.py instead of defining its own
```

### CONFLICT-2: Two Parallel ALNS Operator Hierarchies

| Hierarchy | Tour Type | Matrix Type | TW Support |
|-----------|-----------|-------------|------------|
| `sota_tsp/destroy_ops.py` + `repair_ops.py` | `List[int]` | `List[List[float]]` | None (pure TSP) |
| `sota_common/destroy_operators.py` + `repair_operators.py` | `List[str]` | `Dict[str, Dict[str, float]]` | Stubbed (broken) |

The `sota_tsp` versions are clean and correct for pure TSP. The `sota_common` versions were written for CVRPTW but have broken TW feasibility checks. **Recommendation:** Delete the `sota_common` repair operators and port the `sota_tsp` versions to accept an optional TW feasibility callback.

### CONFLICT-3: Two Haversine Functions

| Function | File | Earth Radius | Unit |
|----------|------|-------------|------|
| `haversine_distance` | `uniride_core/algorithms/distance.py:43` | 6,371,000 m | meters |
| `haversine_distance_km` | `uniride_core/algorithms/route_metrics.py:15` | 6,371 km | kilometers |

These are mathematically equivalent (differ only by ×1000 scale). **Recommendation:** `route_metrics.py` should delegate to `distance.py:haversine_distance` and divide by 1000.

## 5. Methodology Notes

This audit was performed using CodeGraph MCP tools (`codegraph_explore`) to trace actual logic from:
- Objective functions down to specific operators (mutation, crossover, local search, split decoders)
- Destroy/repair operator call paths in ALNS
- Velocity update equations in PSO
- Split decoder constraint satisfaction in CVRPTW
- Distance matrix construction and rounding rules
- Random seed propagation through solver hierarchies

No assumptions were made based on algorithm names — all verdicts are backed by verbatim source code evidence retrieved via CodeGraph.

### Algorithms Verified Clean (No Issues Found)

The following algorithms passed all checks and require no immediate action:

- **bildiri2026 GA** — Correct OX crossover, tournament selection, 2-opt memetic polish, seeded RNG
- **bildiri2026 PSO** — Correct Clerc-style discrete velocity (swap-sequence), inertia/cognitive/social coefficients, periodic reinit
- **bildiri2026 GWO** — Correct swap-sequence movement toward alpha/beta/delta, exponential decay of `a`, memetic 2-opt polish
- **bildiri2026 HHO** — Correct Lévy flight (Mantegna), soft/hard besiege with dives, escape energy decay
- **Split Decoder (Prins)** — Correct capacity checking, time-window backward/forward scheduling, FIX-01 through FIX-05 applied
- **R2DMA-TSP** — Correct resonance-based partner selection, constructive/moderate/destructive crossover modes

### GA-Split Warning (Non-Critical)

The GA-Split fitness function at `ga_split_engine.py:124` uses `fitness = 1.0 / (total_cost + num_vehicles * 50)` with a hardcoded vehicle penalty of 50. This is a design choice, not a bug — but the magic number should be a named constant for reproducibility across experiments.
