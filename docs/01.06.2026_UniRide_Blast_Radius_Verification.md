## §6.9 — Fix the ShawRemoval max_dist bug

**Verdict: ✅ SAFE TO FIX** (very low blast radius)

### Blast radius

| Symbol | Location | Callers | Test Coverage |
|---|---|---|---|
| `ShawRemoval` (sota_common) | `destroy_operators.py:168` | 2 (`__init__.py` re-export) | ✅ `test_sota_e2e.py` |
| `ShawRemoval` (sota_tsp) | `sota_tsp/destroy_ops.py:47` | 6 (`alns_tsp.py`, `e2bso_tsp.py`, `paoea_tsp.py`, `r2dma_tsp.py`) | ⚠️ No direct tests |

### Key finding: **There are TWO ShawRemoval classes**

1. **`sota_common/destroy_operators.py:168`** — uses `Dict[str, Dict[str, float]]` distance matrix. **HAS THE BUG** (`max_dist` initialized to 1.0, never updates on missing distances at line 222–226).
2. **`sota_tsp/destroy_ops.py:47`** — uses `List[List[float]]` distance matrix. **DOES NOT HAVE THE BUG** (sorts by `dm[ref][node]` directly, no normalization).

### Fix

Only the `sota_common` version needs fixing. The bug is at lines 222–226:

```python
# Current (buggy):
max_dist = 1.0
for node in remaining:
    d = dist.get(seed_node, {}).get(node, 0.0)
    if d > max_dist:
        max_dist = d

# Fixed:
max_dist = max(
    (dist.get(seed_node, {}).get(node, 0.0) for node in remaining),
    default=1.0,
) or 1.0
```

**Only 2 callers** (the `__init__.py` re-export and `test_sota_e2e.py`). The fix is a one-line change with test coverage already in place.
