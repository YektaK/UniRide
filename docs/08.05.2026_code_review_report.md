3. Updated High-Severity Findings

---------------------------------

### H1. SOTA resume reuses early run indices

Relevant area:

* master_sota_engine.py

Why it matters:

* breaks deterministic resume semantics
* can duplicate early stochastic trajectories
* contaminates aggregated results

Recommended fix:

* compute effective_run_idx from saved_runs plus local_run_idx
* use effective_run_idx in seed generation and raw result rows
* add a regression test for partial-cache continuation

* * *

### H2. Dashboard robustness plots are methodologically invalid under current output semantics

Relevant areas:

* master_numba_engine.py
* master_sota_engine.py
* dashboard.py

Why it matters:

* Numba contributes aggregated benchmark rows
* SOTA contributes per-run rows
* the dashboard treats them both as raw multi-run observations

Recommended fix:

* split run-level and aggregate-level outputs explicitly
* use run-level rows only for box plots and robustness analysis
* keep leaderboards on aggregate summaries only

* * *

### H3. nb_three_opt public API appears to be a semantic stub

Relevant area:

* bildiri2026

Final position:

If the cited implementation from the secondary audit is current, this should be treated as a high-priority correctness issue, not merely a performance issue.

Why it matters:

* a function advertised as 3-opt but delegated to 2-opt is semantically misleading
* callers do not receive the neighborhood class implied by the API
* any benchmark or algorithm branch expecting 3-opt behavior is underpowered without being told so

Recommended fix:

* either implement true 3-opt behavior
* or rename/deprecate the API so it no longer overclaims

* * *

### H4. MultiLayerLS likely lost convergence semantics relative to its source adaptation

Relevant area:

* ls_engine.py

Final position:

The structural regression is credible and important. The claim that it causes 30–50% quality loss is not established and should not be repeated without measurement.

Why it matters:

* a single pass through layered neighborhoods is not equivalent to repeated improvement-to-stability
* one neighborhood often unlocks improvements for another
* solution quality can degrade materially on harder instances

Recommended fix:

* restore iterative convergence behavior with a bounded repeated-improvement loop
* keep a time budget or iteration ceiling to control runtime
* add a test case where multiple passes outperform one pass

* * *

### H5. R2DMA resonance is partly rotation-sensitive in a cyclic tour domain

Relevant area:

* r2dma_tsp.py

Why it matters:

* equivalent tours under rotation can score lower than they should
* partner selection and crossover mode decisions become biased by arbitrary array alignment
* this is a semantic weakness, not just a style issue

Recommended fix:

* canonicalize tours before position-based comparison
* or redesign resonance dimensions around cycle invariants and edge structure
* add invariance tests for rotation and, if intended, reversal
