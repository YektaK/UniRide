# Paper-scale run plan: template and approval procedure

Gate D item D-10 (plan `docs/superpowers/plans/2026-10-23-gate-d-analysis-documentation-publication.md`, lines 258-265). Modelled on [`WP_E10_RUN_README_TEMPLATE.md`](WP_E10_RUN_README_TEMPLATE.md). Every paper-scale campaign (Bildiri 2026, YAEM 2026) is run under one filled copy of this template. This template decides no scientific value: run counts, levels and limits are placeholders that name the owner question (OQ-n, DECISION_LOG A18) whose answer fills them. Smoke or pilot runs under no plan produce no superiority, causality or proof claim (AGENTS.md).

Contracts cited below: `manifest.*` = `RunManifestV1` (`uniride-run/v1`, one manifest per run), `index.*` = `RunIndexV1` (`uniride-run-index/v1`, one index per campaign), `study.*` = `StudyManifestV1` (profile `study.json`), `plan.*` = `AnalysisPlanV1` (`analysis_plan.json`). Files of a finished campaign: `run_index.json`, `manifests/<run_id>.json` (each with a detached `.sha256`), the result files, `report.json`/`report.txt` (`academic_benchmark/analysis/manifests.py:48-49`, `academic_benchmark/studies/run.py:410-415`). `python -m academic_benchmark.studies.verify_manifests <dir>` recomputes all checksums (`academic_benchmark/studies/verify_manifests.py:1-30`).

**Citations.** Every `file:line` in this template refers to commit `a75cdde1` and is informative: lines move when the code changes, and the reviewer re-reads the named field in the contract. The consistency test checks the cited contract fields by name, not the line numbers.

## Procedure

1. **Draft.** The lead copies this template into a run-plan file and fills every row of the field table. A value that is not yet decided stays a placeholder and the plan is not offered for approval. The filled plan lives at `docs/run_plans/<study_id>-<YYYY-MM-DD>.md` and is committed, so that its sha256 can be recorded in DECISION_LOG (lead decision 2026-10-24).
2. **Prepare.** The lead prepares (not merges) the profile as it will run: `study.status` set to `active`, the owner-approved values in `study.algorithm_parameters`, `study.run_count`, `study.scaled_fixed_budget_levels`, `study.secondary_protocol`, and `plan.status` set to `active` with `plan.minimum_n_per_cell` set and `plan.unresolved` empty. The two file hashes in the plan are the hashes of these prepared files (the same bytes the run service hashes, `academic_benchmark/studies/run.py:205-206`).
3. **Estimate.** The D-04b2 estimate is measured on the machine that will run the campaign and attached (row "Estimate").
4. **Checklist.** Every checklist row below is verified by the lead and the evidence is written into the plan.
5. **Approval** (next section).
6. **Run.** The run service is started in paper mode from a clean checkout of the approved commit, with an output folder outside the repository. It refuses a profile that is not active, an analysis plan that is not active, a dirty or unknown tree and an output folder inside the repository (`academic_benchmark/studies/run.py:440-456`).
7. **After the run.** `verify_manifests` passes; the reviewer reads the "Check after the run" column of every field row against the approved plan and records the result. Any difference makes the campaign not paper evidence (below). A changed profile, analysis plan, commit, environment or seed protocol cannot be resumed; it needs a new plan and a new approval.

## Approval

The owner approves the run plan in chat. The lead then records one DECISION_LOG entry (A-series) that names the plan file, its sha256 and the owner's approval, and sets the profile `status: active` (and the analysis plan `status: active`) in the same lead-merged commit as that entry. The plan states the base commit it was prepared on; the approved campaign commit is that commit plus this approval commit. (Lead decision 2026-10-24.) A plan file cannot contain the hash of the commit that contains it, and the profile hash in the plan is the hash of the activated profile, so the plan names the parent commit and the manifest commit must differ from it only by the approval commit; the reviewer checks it with `git diff --name-status <base commit> <index.git.commit>`, which may list only the profile status line, the analysis-plan status line, DECISION_LOG and the plan file.

A run whose manifest commit, profile hash or analysis-plan hash differs from the approved plan is not paper evidence. A run with `index.mode` other than `paper`, `index.git.dirty` true, or `index.status` failed without every failure listed in the failed-run file is not paper evidence either. Approved plans are never edited in place; a change is a new plan, a new sha256 and a new approval.
