Command block (to be pasted into the closing item's brief). Every command runs through `Invoke-Limited`, which starts the process with `Start-Process`, caches its handle (`$null = $p.Handle`, without which `ExitCode` can be empty after a `-NoNewWindow` start), redirects stdout and stderr to files under `C:\wt\gated`, waits with `WaitForExit(<ms>)` and, on timeout, stops **only that PID** (`Stop-Process -Id`, never `taskkill /IM`) and prints `FAIL TIMEOUT`. On a normal exit it prints the exit code; a non-zero **or empty** exit code is a failure. `git status --short` exits 0 even when files are listed, so its `.out.txt` must also be empty. **Argument rule:** `Start-Process -ArgumentList` joins the array with single spaces and does not quote elements, so any argument that contains a space must carry its own escaped double quotes inside the element (for example `'"not requires_ampl"'`); otherwise pytest receives `-m not requires_ampl` and fails. A pytest run stopped this way leaves its child processes, if any, to be listed with `Get-CimInstance Win32_Process -Filter "ParentProcessId=<pid>"` and stopped by PID. Limits are generous multiples of the recorded baseline (academic suite 464.8 s at `559826b5`); the smoke and API limits are [A] because no timing is recorded for them.

function Invoke-Limited([string]$Name, [int]$Seconds, [string[]]$ArgList, [string]$Exe = $PY) {
  $p = Start-Process -FilePath $Exe -ArgumentList $ArgList -NoNewWindow -PassThru -RedirectStandardOutput "C:\wt\gated\$Name.out.txt" -RedirectStandardError "C:\wt\gated\$Name.err.txt"
  $null = $p.Handle  # cache the handle so ExitCode is readable after the process ends

  if ($null -eq $code -or "$code" -eq "" -or $code -ne 0) { "FAIL $Name exit '$code'" } else { "OK $Name exit 0" }
